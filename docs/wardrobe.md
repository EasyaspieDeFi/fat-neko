# Wardrobe — Finch-style cosmetics for Fat Neko

Branch: `feat/finch-wardrobe`. Status: core loop shipped with placeholder art.

The goal was the part of Finch that actually drives retention: unlock things, choose what
to wear, be seen wearing it. Everything here is in `index.html` plus `assets/cosmetics/`.

## Why the layers work the way they do

The cat is not DOM. He is a single 300 × 272 PNG blitted to a `<canvas>` every frame with
`imageSmoothingEnabled = false`, scaled by the log of his weight, squashed when he eats and
again on an idle blink roughly every 4 seconds.

So a cosmetic is **another PNG drawn into the same dest rect**, expanded to a 400 × 400
"doll" canvas that places the base sprite at (50, 112). Because the rect is shared, growth,
squash and blink apply to clothing for free and no garment ever needs re-anchoring. The
doll canvas exists purely to add headroom: the base sprite is cropped so tight that his
ears touch y=0, leaving nowhere to put a hat.

```
drawCosmetics(ctx, dx,dy,dw,dh, behind=true)   ← capes, wings, auras
ctx.drawImage(NEKO_IMG, dx,dy,dw,dh)
drawCosmetics(ctx, dx,dy,dw,dh, behind=false)  ← body → head → face → offhand → hand, by slot z
```

Both the live hero canvas and the shareable Chonk Card call the same pair.

## Three ways to unlock, on purpose

| Source | Items | Mechanism |
|---|---|---|
| Weight milestones | 12 | `ladderIdx() >= rung` against the existing 24-rung `LADDER` |
| Login streaks | 7 | `S.streak >= day` at 3 / 7 / 14 / 30 / 60 / 100 / 365 |
| 🧶 Yarn shop | 59 | one **themed set** stocked per day, cycling through the sets |

Weight unlocks are deliberately bunched at rungs 2–8. Free play caps at `FREE_CAP`
(rung 8, "a grown adult"), so a wardrobe spread evenly across all 24 rungs would read as a
paywall. Eight reachable items plus four distant prestige ones reads as a goal instead.

Milestones drop a specific item — that is the trophy feeling. Yarn buys a *choice*, which
is the part that actually pulls people back daily. Finch runs on the second one.

## Yarn stays away from $FATNEKO

Yarn is earned from daily quests and check-ins, and **cannot be bought with money or
tokens**. If clothes cost $FATNEKO, the wardrobe would compete with the burn loop for the
same wallet and free players would get nothing. Growth stays burn-only; cosmetics stay
play-only. The two economies never touch.

## Streak freezes

Missing one day used to reset a 100-day streak to 1 — the single worst churn moment in a
daily-return app. A 🧶 75 freeze covers exactly one missed day, consumed automatically in
`claimDaily()`. Capped at 3 held.

## State

Added to `S`, so it rides the existing CloudStorage + localStorage mirror:

```js
owned: []        // unlocked cosmetic ids
equipped: {}     // slot -> id
yarn: 0
freezes: 0
q: {day, prog, done}    // today's quest progress
shop: {day, ids}        // today's shop lineup, latched
```

The shop lineup is latched into state on first view of the day rather than derived live
from the unowned pool — otherwise buying something reshuffles the whole shop.

Boot grants any milestone an existing player already earned (`checkUnlocks(true)`) and then
drops the reveal queue, so upgrading finds you a full wardrobe instead of twelve modals.

## Art pipeline

`assets/cosmetics/art.json` maps id → path and is generated by `tools/sync_cosmetics.py`
scanning the directory. A hand-drawn `assets/cosmetics/<id>.png` always beats the generated
`_gen/<id>.png`. The manifest exists because the site is static — the browser has no way to
list a directory — and because probing both paths cost a 404 per item in the console.

`tools/gen_placeholder_cosmetics.py` regenerates all 28 placeholders, the contact sheet and
the author templates. Placeholders are stand-ins for real art; see
`assets/cosmetics/README.md` for the artist-facing brief.

## Known gaps

- **Cosmetics are local.** `S.equipped` is shaped to drop into the NFT checkpoint payload
  later so `tokenURI` can render the dressed cat on marketplaces, but nothing on-chain
  reads it yet.
- **The leaderboard shows names, not outfits.** The Chonk Card carries the outfit, which
  closes the loop for sharing; seeing other players' nekos dressed would close it harder.
- **No backgrounds/rooms yet.** The canvas already draws a room; a full-frame PNG slot is
  the cheapest large win still on the table.

## Themed sets

Every cosmetic carries a `set`. Items predating sets are backfilled as `core` (the
weight/streak trophies) or `classic` (the original shop items).

| Set | Items | Notes |
|---|---|---|
| `core` | 19 | weight rungs + streak days — the trophy items |
| `classic` | 9 | the original shop lineup |
| `fantasy` | 10 | LOTR-flavoured armour + weapons; the only set spanning both hands |
| `street` `y2k` `worldcup` `goth` `alt` `prep` `jock` `nerd` | 5 each | one theme per day in the shop |

The shop stocks **one set per day** rather than four unrelated pieces — a coherent
"today is Goth day" is a better reason to return, and stocking a set together is the
only way a full themed outfit realistically gets assembled. If the day's set is fully
owned the picker walks to the next set with stock, so completionists never hit an
empty shelf. `buyCos` re-checks stock server-of-record style, so the rotation can't be
bypassed by calling the handler directly.

Wearing 3+ items that all share a set shows a **full-fit badge** in the wardrobe. It is
deliberately cosmetic: a stat bonus would compete with burning, which is meant to be
the only thing that actually grows the cat.
